# 알짜 블로그 UI 명세서 (디자인 시안용)

> 작성일: 2026-10-26 / 개정: 2026-10-26 (상호작용·이동·로딩 상세 추가)
> 전제: 이 문서는 **현재 사이트 그대로의 동작**을 적는다. 사이트 디자인·기능은 건드리지 않았고, 문서만 세밀하게 보강했다.
> 시안 제작 시 이 문서의 구조·동작을 기준으로 삼고, 스타일만 새로 설계한다.

## 0. 전체 동작 원칙 (시안 전에 꼭 알아야 할 것)

- **MPA(다중 페이지)**: 모든 이동은 전체 페이지 새로고침(브라우저 기본 동작). SPA 라우터, 페이지 전환 애니메이션, 로딩 스피너는 사이트 어디에도 없다.
- **SSG(빌드 시 정적 생성)**: 모든 HTML은 배포 전에 미리 만들어진다. 요청 시 서버 계산이 없다.
- **버튼 부재**: 사이트 전체에 `<button>` 요소가 없다. 모든 이동·동작은 링크(`<a>`) 클릭 또는 검색 입력(`input` 이벤트)으로 이루어진다.
- **클라이언트 JS는 3곳뿐**: (1) 검색 페이지의 Pagefind 로딩, (2) 설정 시 Giscus 댓글 스크립트, (3) 설정 시 Cloudflare 분석 비콘. 그 외 페이지에는 JS가 없다.
- **외부 링크 없음**: 현재 UI에 새 창 링크(`target=_blank`)는 없다. 모든 링크는 같은 탭 이동이다.

## 1. 공통 레이아웃 (모든 페이지 동일, `src/layouts/Base.astro`)

### 1.1 head (눈에 안 보이지만 시안·SEO에 영향)

- title 규칙: 글 페이지 `글 제목 | 알짜`, 그 외 `페이지 제목 | 알짜`, 홈은 `알짜`
- description, canonical, OG/Twitter 메타, RSS alternate 링크 포함
- 글 페이지에만 JSON-LD 삽입 (Article 필수, FAQPage는 FAQ 있을 때만)
- Cloudflare 분석 비콘: 토큰 설정 시에만 삽입 (현재 미설정 → 없음)

### 1.2 헤더

| 요소 | 형태 | 클릭 시 이동 | 비고 |
|---|---|---|---|
| 로고 "알짜" | 텍스트 링크 | `/` (홈) | 항상 표시 |
| "소개" | 텍스트 링크 | `/about/` | 항상 표시 |
| "RSS" | 텍스트 링크 | `/rss.xml` (XML 피드) | 항상 표시 |

- 헤더에 검색 링크는 없다. 검색은 URL(`/search/`) 직접 입력으로만 접근 가능.
- 모바일 전용 메뉴(햄버거 등)는 없다. 헤더는 가로 나열 그대로 유지된다.

### 1.3 본문 영역

- 최대폭 768px 가운데 정렬, 좌우 패딩 16px, 상하 패딩 32px
- 본문(글) 최대폭 720px, 17px / 행간 1.8

### 1.4 푸터

- "© 연도 알짜 · 사이트 설명" 텍스트 1줄. 링크·버튼 없음.

## 2. 페이지별 상세

### 2.1 홈 `/` (파일: `src/pages/[...page].astro`)

**구성 요소:**

| 요소 | 형태 | 클릭 시 이동 | 비고 |
|---|---|---|---|
| 사이트명 h1 | 화면에 안 보이는 텍스트(sr-only) | 없음 | SEO용, 시각적 제목은 없음 |
| 히어로 이미지 (1페이지만) | 이미지 | 없음 | `public/hero/` 정지 이미지 위에 페이지 로드 뒤 움직임을 얹음. 동작 줄이기 설정이면 정지 이미지만. 문구는 이미지에 포함. 2페이지부터는 태그라인 텍스트 |
| 글 제목 | 굵은 텍스트 링크 | `/posts/[slug]/` | 목록의 유일한 링크 |
| 글 설명 | 일반 텍스트 | 없음 | 클릭 불가 |
| "날짜 · 카테고리" | 작은 회색 텍스트 | 없음 | 카테고리명은 텍스트일 뿐 링크가 아님 |
| "← 이전" | 텍스트 링크 | 이전 페이지 (`/` 또는 `/(n-1)`) | 첫 페이지에서는 표시 안 됨 |
| "다음 →" | 텍스트 링크 | 다음 페이지 (`/n`) | 마지막 페이지에서는 표시 안 됨 |

**동작 규칙:**

- 목록 순서: 발행일 내림차순. 페이지당 10개, `/`가 1페이지, `/2`, `/3` … 으로 이어짐.
- 초안(`draft: true`) 글은 목록에서 제외.
- 로딩: 없음. 빌드된 HTML 그대로 표시, JS 없음.
- 빈 상태: 글이 0개면 목록이 비어 보임 (현재 3개라 해당 없음).

### 2.2 글 상세 `/posts/[slug]/` (파일: `src/layouts/Post.astro` — 핵심 페이지)

**위에서 아래 순서대로 렌더링된다:**

| 순서 | 요소 | 형태 | 클릭 시 이동 / 동작 | 비고 |
|---|---|---|---|---|
| 1 | 브레드크럼 "홈" | 텍스트 링크 | `/` | |
| 2 | 브레드크럼 "카테고리명" | 텍스트 링크 | `/category/[카테고리명]/` | 한글 등 비ASCII는 URL 인코딩됨 |
| 3 | 제목 h1 | 큰 굵은 텍스트 | 없음 | 링크 아님 |
| 4 | 메타줄 | 작은 회색 텍스트 | 없음 | "발행일 · (업데이트일) · 카테고리 · 약 N분". 읽기 시간 = 본문 글자수 ÷ 600, 최소 1분 |
| 5 | 핵심 요약 박스 | 회색 배경 박스 | 없음 | "핵심 요약" 라벨 + 요약 문단. summary 없으면 description 사용 |
| 6 | 목차 박스 | 테두리 박스 + 링크 목록 | `#제목-슬러그` 앵커로 본문 위치로 점프 | h2~h3만 추출, h3은 들여쓰기. 제목 없으면 박스 자체가 안 나옴 |
| 7 | AI 방어 숨김 div | 눈에 안 보임 (1px, aria-hidden) | 없음 | `AI_DEFENSE_HTML` 설정 시에만 렌더링. **현재 미설정 → 없음** |
| 8 | 본문 | 텍스트·표·인용구 | 본문 내 작성자 링크가 있으면 해당 URL로 이동 (현재 샘플 글에는 없음) | h2는 하단 경계선, 표는 전체폭·헤더 회색 배경, 인용구는 좌측 파란 경계선 |
| 9 | FAQ 섹션 | "자주 묻는 질문" 제목 + Q/A 목록 | 없음 | **아코디언 아님, 항상 펼쳐진 상태.** FAQ 없으면 섹션 자체가 안 나옴 |
| 10 | 태그 목록 | `#태그` 텍스트 링크들 | `/tag/[태그명]/` | 태그 없으면 표시 안 됨 |
| 11 | 이전/다음 글 네비게이션 | 텍스트 링크 | 왼쪽 "← 이전 글 제목" = 더 오래된 글, 오른쪽 "다음 글 제목 →" = 더 최신 글 | 날짜 기준 정렬. 처음·마지막 글에서는 해당 방향 링크가 안 나옴 |
| 12 | 관련 글 섹션 | "관련 글" 제목 + 제목 링크 목록 | `/posts/[slug]/` | 같은 카테고리 글 중 최신순 최대 3개, 자기 자신 제외. 없으면 섹션 자체가 안 나옴 |
| 13 | 카나리아 문구 | 눈에 안 보임 (1px, 투명, 선택 불가, aria-hidden) | 없음 | `CANARY_STRING` 설정 시에만 렌더링. **현재 미설정 → 없음** |
| 14 | 댓글 영역 | Giscus 위젯 | 위젯 내 댓글 작성·리액션 (Giscus 자체 동작) | **4개 설정값이 모두 입력돼야 렌더링. 현재 미설정 → 없음.** 설정 시: giscus.app 외부 스크립트 로드, 테마 light, 언어 ko, 입력창 하단, 리액션 켜짐, 글 경로(pathname) 기준 스레드 |

**로딩:**

- 페이지 자체: 빌드된 HTML, 로딩 표시 없음.
- 목차 앵커 점프: 브라우저 기본 스크롤 이동, 즉시.
- Giscus(설정 시): 페이지 로드 후 외부 스크립트가 위젯을 채움. 로딩 문구·스피너 없음.
- 그 외 JS 없음.

### 2.3 카테고리 `/category/[이름]/` (파일: `src/pages/category/[name].astro`)

| 요소 | 형태 | 클릭 시 이동 | 비고 |
|---|---|---|---|
| 카테고리명 h1 | 굵은 텍스트 | 없음 | |
| 글 제목 | 굵은 텍스트 링크 | `/posts/[slug]/` | |
| 글 설명 | 일반 텍스트 | 없음 | |

- 날짜·카테고리 표시 없음 (홈과 다름).
- 페이지네이션 없음. 해당 카테고리 글 전체를 한 페이지에 표시.
- **주의: 목록 순서가 날짜순 정렬이 아니다.** 코드에 정렬 로직이 없어 빌드 시 컬렉션 로딩 순서대로 나온다. 홈과 동작이 다르다.
- 존재하지 않는 카테고리 URL은 빌드 시 생성되지 않으므로 접근 불가.

### 2.4 태그 `/tag/[이름]/` (파일: `src/pages/tag/[name].astro`)

- 카테고리 페이지와 동일 구조. h1은 `#태그명`, title은 `#태그명`.
- 페이지네이션 없음, 날짜순 정렬 없음 (카테고리와 동일).

### 2.5 소개 `/about/` (파일: `src/pages/about.astro`)

- 정적 소개 문단 2개 + "문의: 사이트 내 댓글을 이용해 주세요." 문구 1줄.
- 클릭 가능한 요소는 헤더·푸터뿐. 페이지 자체에는 링크·버튼 없음.
- **주의: 소개 문구는 댓글 이용을 안내하지만, Giscus 미설정 상태라 실제 댓글 UI가 없다.** 시안 적용 전후로 댓글 설정과 함께 정리할 항목.

### 2.6 검색 `/search/` (파일: `src/pages/search.astro`)

| 요소 | 형태 | 동작 |
|---|---|---|
| 제목 "검색" h1 | 굵은 텍스트 | 없음 |
| 검색 입력창 | `type=search` 입력 필드, 플레이스홀더 "검색어를 입력하세요" | 아래 동작 참조 |
| 결과 목록 영역 | 빈 div | 검색 결과로 채워짐 |

**검색 동작 (버튼·엔터 제출 없음, 입력 이벤트만으로 동작):**

1. 사용자가 한 글자라도 입력하면 `input` 이벤트 발생.
2. 입력값이 비어 있으면 결과 영역을 비움.
3. 입력값이 있으면 **첫 검색 시에만** `/pagefind/pagefind.js`를 동적 로딩 후 초기화. 이후 입력부터는 로딩된 인스턴스 재사용.
4. 상위 10개 결과를 제목 링크 + 발췌문 형태로 표시. 제목 클릭 시 해당 글 페이지로 이동 (전체 새로고침).
5. 결과 0개면 "검색 결과가 없습니다." 텍스트 표시.
6. 검색 대상은 발행된 모든 글의 전문. 인덱스는 빌드 시(postbuild) 생성됨.

**로딩:**

- 첫 입력 시 pagefind.js + 인덱스 조각을 네트워크로 가져옴. **이때 로딩 문구·스피너가 없다.** 결과가 올 때까지 결과 영역은 이전 상태 그대로.
- 두 번째 입력부터는 로딩 없음 (이미 메모리에 있음).

### 2.7 RSS `/rss.xml` (파일: `src/pages/rss.xml.ts`)

- XML 피드, 사람용 UI 없음. 헤더 "RSS" 링크와 head alternate 링크로 연결.
- 항목: 발행일 내림차순, 제목·설명·발행일·글 링크 포함. 초안 제외.

### 2.8 시스템 경로 (디자인 대상 아님, 동작만 기록)

| 경로 | 내용 | 비고 |
|---|---|---|
| `/sitemap-index.xml`, `/sitemap-0.xml` | 사이트맵 (빌드 시 자동 생성) | robots.txt에서 참조 |
| `/robots.txt` | 정적 파일. AI 학습용 크롤러 차단 + 온디맨드 봇 허용 + 사이트맵 주소 | |
| `/llms.txt` | 빌드 시 자동 생성. 카테고리별 글 목록 (제목 + 설명 + 절대 URL) | |
| `/pagefind/` | 검색 인덱스 파일들 (빌드 시 자동 생성) | 사람용 페이지 아님 |

## 3. 이동 흐름 (링크 그래프)

```
홈(/) ──글 제목──▶ 글 상세(/posts/[slug]/)
  │                    │──브레드크럼──▶ 홈 / 카테고리
  │                    │──목차───────▶ 같은 페이지 내 앵커 점프
  │                    │──태그───────▶ 태그 페이지
  │                    │──이전/다음──▶ 다른 글 상세
  │                    │──관련 글────▶ 다른 글 상세
  │                    │──댓글(설정 시)──▶ Giscus 위젯 (페이지 내)
  │
  ├──헤더 "소개"──▶ 소개(/about/)──▶ (헤더로만 복귀)
  ├──헤더 "RSS"───▶ RSS 피드(/rss.xml)
  ├──이전/다음───▶ 홈 페이지네이션(/2, /3…)
  │
  └──(직접 URL 입력)──▶ 검색(/search/)──▶ 결과 제목──▶ 글 상세
카테고리(/category/[이름]/) ──글 제목──▶ 글 상세
태그(/tag/[이름]/) ──글 제목──▶ 글 상세
```

- 모든 이동은 같은 탭, 전체 새로고침. 뒤로가기는 브라우저 기본 동작.
- 검색·카테고리·태그 페이지로 가는 헤더 메뉴는 없다 (직접 URL 또는 글 내 링크 경유).

## 4. 로딩 시점 총정리

| 시점 | 일어나는 일 | 로딩 UI |
|---|---|---|
| 빌드 시 (배포 전) | 전 페이지 HTML, 사이트맵, RSS, llms.txt, Pagefind 인덱스 생성 | 해당 없음 |
| 페이지 요청 시 | Cloudflare가 빌드된 정적 HTML 그대로 서빙. 서버 계산 없음 | 없음 |
| 페이지 간 이동 시 | 전체 문서 새로고침 (브라우저 기본) | 없음 (브라우저 자체 표시만) |
| 검색 첫 입력 시 | pagefind.js + 인덱스 조각 네트워크 로딩 | 없음 |
| 검색 두 번째 입력부터 | 메모리 내 인스턴스 재사용 | 없음 |
| 글 페이지 로드 시 (Giscus 설정 시) | giscus.app 스크립트 로드 후 위젯 채움 | 없음 |
| 글 페이지 로드 시 (분석 토큰 설정 시) | Cloudflare 비콘 스크립트 로드 | 없음 |

## 5. 존재하지 않는 기능 (시안에서 새로 만들지 말 것 — 만들려면 별도 결정 필요)

- 로그인·회원가입, 글 작성·편집 UI, 좋아요, 공유 버튼, 다크 모드, 모바일 햄버거 메뉴, 무한 스크롤, 뉴스레터 구독, 광고 슬롯 (AdSense는 글 20~30개 후 별도 결정)
- 이미지: 현재 파비콘 외 글 이미지는 없음. 글에 이미지를 넣으려면 Markdown에 직접 추가하는 방식.

## 6. 콘텐츠 모델 (글 frontmatter, `src/content/posts/*.md` 1파일 = 1글)

| 필드 | 필수 | 설명 |
|---|---|---|
| title | O | 글 제목 |
| description | O | 1~200자, 목록·검색·메타 설명에 사용 |
| date | O | 발행일 |
| updated | - | 갱신일 (있으면 메타줄에 "업데이트" 표시 + JSON-LD dateModified) |
| category | O | 카테고리 1개 |
| tags | - | 태그 배열 (기본 빈 배열) |
| draft | - | true면 발행 제외 (기본 false) |

| faq | - | Q/A 배열 (기본 빈 배열, 있으면 FAQ 섹션 + FAQPage JSON-LD) |

## 8. 디자인 적용 시 제약

- **정적 사이트 유지**: 서버 로직·DB·로그인 추가 불가. 모든 페이지는 빌드 시 HTML로 생성됨.
- **구조 유지**: 핵심 요약 박스, 목차, FAQ, 표 중심 본문, JSON-LD는 SEO/GEO의 핵심이라 스타일은 바꿔도 구조·순서는 유지.
- **설정 집중**: 사이트명·URL·댓글·분석·방어 문구는 `src/config.ts` 한 곳에서 관리.
- **색상 토큰 (현재값)**: 본문 #1f2937, 보조 #6b7280, 강조 #2563eb, 경계 #e5e7eb, 연한 배경 #f9fafb, info #eff6ff, warn #fefce8, summary #f3f4f6 — 시안에서 자유롭게 교체 가능.
- **폰트**: 현재 시스템 폰트 스택, 웹폰트 미사용 — 시안에서 웹폰트 도입 가능 (빌드·로딩 영향만 고려).
- **반응형**: 현재 최대폭 중심의 단순 구조라 모바일 대응은 시안에서 새로 설계 가능 (특히 헤더 네비게이션).
