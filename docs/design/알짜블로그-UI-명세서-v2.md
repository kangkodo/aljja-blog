# 알짜 블로그 UI 명세서 v2 (시안 반영판)

> 작성일: 2026-10-27 / 기준: 디자인 캔버스 "알짜 블로그 시안" 13장
> v1(2026-10-26)은 **현재 사이트 동작**을 적은 문서였다. v2는 **시안대로 바꾼 뒤의 목표 동작**을 적는다.
> 개발 중 v1과 v2가 충돌하면 v2를 따른다. 0장에 바뀐 점을 모아 두었다.

## ⚠ 개발 필수 체크리스트 (구현하는 사람·에이전트는 먼저 읽을 것)

시안에 그림으로는 안 보이지만, 빠뜨리면 실제 사이트에서 문제가 되는 동작이다. 구현 완료 전에 하나씩 확인한다.

- [ ] **페이지가 1개뿐이면 홈의 페이지 이동 영역 전체를 렌더링하지 않는다.**
  - 이유: 지금 글이 3개라 홈은 1페이지뿐이다. 조건 없이 만들면 흐린 "← 이전", 숫자 "1", 흐린 "다음 →"만 덩그러니 보인다.
  - 구현: Astro `paginate()` 결과에서 `page.lastPage === 1`이면 `<nav aria-label="페이지 이동">`를 출력하지 않는다.
  - 확인: 글 10개 이하 상태로 빌드해서 홈 하단에 페이지 이동이 없는지 본다. 글을 11개 이상으로 만들어 빌드하면 나타나는지도 본다.
- [ ] **검색 페이지는 주소의 `?q=` 값으로 바로 검색한다.**
  - 이유: 헤더 검색창에서 Enter를 누르면 `/search/?q=검색어`로 이동한다. 검색 페이지가 이 값을 읽지 않으면 빈 검색 화면이 떠서, 방문자가 다시 입력해야 한다.
  - 구현: 검색 페이지 스크립트가 로드 시 `new URLSearchParams(location.search).get('q')`를 읽어 입력창에 채우고, 값이 있으면 검색을 1회 실행한다 (기존 `input` 이벤트 처리 함수를 그대로 호출).
  - 확인: 아무 페이지의 헤더 검색창에 "전입신고"를 입력하고 Enter → 검색 페이지에 결과가 바로 보이는지 본다.
- [ ] **AdSense 승인 전에는 광고 마크업을 출력하지 않는다.** (8장, `ADS_ENABLED` 플래그)
- [ ] **카테고리·태그 목록은 발행일 내림차순으로 정렬한다.** (v1 버그)
- [ ] **privacy@aljjatip.com은 사이트 어디에도 넣지 않는다.** (7장)
- [ ] **폰트는 IBM Plex Sans KR 400·700만 로드한다.** (2.2)

## 1. 전체 동작 원칙

- **MPA + SSG 유지**: 모든 페이지는 빌드 시 HTML로 생성, 이동은 전체 새로고침. 서버 로직·DB·로그인 없음.
- **이동 속도**: 화면에 보이는 내부 링크는 Astro prefetch(`viewport`)로 미리 받아 둔다. 미리 받은 페이지를 다시 받지 않도록 HTML은 브라우저에 5분 보관한다(`public/_headers`). 이동이 120ms를 넘으면 화면 위에 로고 파랑(`--brand`, `#0052ff`) 3px 로딩 바를 보여 준다 (`NavProgress.astro`, 검색 페이지의 Pagefind 첫 로딩에도 사용).
- **JS는 최소한으로**:
  1. 헤더 검색 토글 (모든 페이지, 수십 줄 이내의 인라인 스크립트)
  2. 검색 페이지의 Pagefind 동적 로딩
  3. 페이지 이동 로딩 바 + Astro prefetch
  4. Cloudflare Web Analytics 비콘 (토큰 설정 시)
- **링크 위주**: 이동은 모두 `<a>`. 버튼은 검색 토글 하나뿐.
- **외부 링크 없음**: 새 창 링크 없음. 메일 주소는 `mailto:` 링크.
- **움직임 줄이기 존중**: `prefers-reduced-motion: reduce`이면 검색창 애니메이션 없이 즉시 열고 닫는다.

## 4. 공통 레이아웃

### 4.1 본문 폭

- 콘텐츠 최대폭 768px 가운데 정렬, 좌우 패딩 16px
- 글 본문(article) 최대폭 720px

### 4.2 헤더

**1줄: 로고**

- 높이 64px(모바일 56px), 로고 가운데 정렬, 클릭 시 `/`
- 로고 이미지 `public/brand/alzza-logo-*.webp/png`, 원본 비율(1280×536) 유지, 높이 36px(모바일 32px)

**2줄: 카테고리 메뉴 + 검색 버튼**

| 요소 | 형태 | 동작 |
|---|---|---|
| "전체" | 링크 | `/` |
| 카테고리명들 | 링크 | `/category/[이름]/` |
| 검색 버튼 | `<button>` 돋보기 아이콘 44×44 | 검색창 펼침/접힘 토글 |

- 카테고리 목록은 **콘텐츠에서 자동 생성** (글 frontmatter의 category 값 모음). 표시 순서는 `src/config.ts`에 배열로 정해 두는 것을 권장.
- 현재 위치 표시: 홈은 "전체", 카테고리 페이지와 글 상세는 해당 카테고리에 `aria-current="page"` + 초록 글자 + 2px 밑줄.
- 소개·검색·개인정보처리방침·404에서는 아무 메뉴도 활성화하지 않는다.
- **데스크톱**: 메뉴 가운데 정렬, 많아지면 다음 줄로 넘어감(wrap). 검색 버튼은 오른쪽 끝에 절대 위치, 메뉴 양옆 64px 패딩으로 겹침 방지.
- **모바일**: 메뉴는 가로 스크롤(줄바꿈 없음), 검색 버튼은 오른쪽에 고정. 왼쪽에 버튼 폭(44px)만큼 여백을 줘서 메뉴가 시각적으로 가운데에 오게 한다.

**3줄: 검색 펼침 영역 (기본 접힘)**

- 펼침/접힘 애니메이션: **0.3초**, `grid-template-rows 0fr↔1fr` + `opacity` + `visibility`, easing `cubic-bezier(0.22, 1, 0.36, 1)`
- 접힌 상태에서는 `visibility: hidden`이라 Tab으로 들어가지 않는다.
- 버튼 상태: `aria-expanded`, `aria-controls="site-search"`, `aria-label`이 "검색 열기"↔"검색 닫기"로 바뀜. 아이콘은 돋보기↔X, 열린 동안 버튼 배경 `--accent-soft`.
- 내용: 검색 입력창(placeholder "검색어를 입력하세요") + 안내문 "Enter를 누르면 검색 결과 페이지로 이동합니다"(데스크톱만)
- **동작**: Enter 시 `/search/?q=<입력값>`으로 이동. 펼친 영역 안에서 결과를 바로 보여주지 않는다 (모든 페이지에 Pagefind를 싣지 않기 위함).
- 권장 구현: `<form action="/search/" method="get" role="search">` + `<input name="q">`. 이렇게 하면 JS가 없어도 Enter로 검색 페이지에 간다. 열 때 입력창에 포커스, Esc로 닫기.

## 5. 페이지별 상세

### 5.1 홈 `/`, `/2`, `/3` …

| 순서 | 요소 | 스타일 | 비고 |
|---|---|---|---|
| 1 | 사이트명 h1 | sr-only | SEO용 |
| 2 | "생활 · 돈 · 행정" | `label`, 초록 | |
| 3 | "알아두면 쓸모있는 정보" | `h2` | 태그라인 |
| 4 | 글 목록 (10개) | 위 굵은 선 + 항목 사이 가는 선 | 각 항목: 날짜 · 카테고리(`caption`) → 제목 링크(`h3`) → 설명(`body-sm`, `--text-3`) |
| 5 | 페이지 이동 | 가운데 정렬 | 5.1.1 참조 |

#### 5.1.1 페이지 이동

- 순서: **← 이전 · 페이지 번호 · 다음 →** (모바일은 ‹ › 아이콘, `aria-label` "이전 페이지"/"다음 페이지")
- 현재 페이지: 44×44 초록 사각형, 흰 글자 700, `aria-current="page"`
- 첫 페이지의 "이전", 마지막 페이지의 "다음": 숨기지 않고 `--disabled` 색 텍스트(`aria-disabled="true"`, 링크 아님)로 둔다. 번호 줄이 좌우로 흔들리지 않게 하기 위함.
- **전체 1페이지면 페이지 이동 영역 전체를 렌더링하지 않는다.** (현재 글 3개라 해당)
- 번호 생략 규칙:
  - 데스크톱 최대 7칸: 총 ≤7이면 전부. 앞쪽(현재 ≤4) `1 2 3 4 5 … N` / 중간 `1 … p-1 p p+1 … N` / 뒤쪽(현재 ≥N-3) `1 … N-4 N-3 N-2 N-1 N`
  - 모바일 최대 6칸: 총 ≤5면 전부. 앞쪽(현재 ≤3) `1 2 3 4 … N` / 중간 `1 … p … N` / 뒤쪽(현재 ≥N-2) `1 … N-3 N-2 N-1 N`
- "…"은 `aria-hidden`.
- 구현: Astro `paginate()`의 `page.currentPage`, `page.lastPage`로 빌드 시 계산.

| 2 | 제목 h1 | `display` | |

| 4 | 핵심 요약 박스 | `--accent-soft` 배경, 모서리 12px. "핵심 요약"(`label`, 초록) + 문단(`body-sm`) | summary 없으면 description |
| 5 | 본문 | `body`. h2는 하단 경계선, 표는 전체 폭·머리 회색 배경, 인용구는 왼쪽 3px 초록 선 | **목차 없음** |
| 5-1 | (본문 중간) 광고 자리 | 8장 참조 | 두 번째 h2 앞 등 본문 중간 |
| 6 | FAQ "자주 묻는 질문" | 제목 `h2`, 질문 `strong-sm`(초록 "Q" 접두), 답변 `body-sm` | 항상 펼침. FAQ 없으면 섹션 없음 |
| 7 | 오류 제보 안내 | `caption`: "정보가 바뀌었거나 틀린 부분을 발견하셨다면 support@aljjatip.com으로 알려 주세요." | 메일 주소는 `mailto:` 링크 |
| 8 | 태그 | `caption` 칩(`--surface-2` 배경, 둥근 모서리) | `/tag/[태그]/`. 없으면 표시 안 함 |
| 9 | 이전/다음 글 | 2칸 카드(모바일은 세로 쌓기). 라벨 `caption`, 제목 `strong-sm` | 처음·마지막 글은 해당 칸 없음 |
| 10 | 관련 글 | 제목 `h3`, 항목 `body-sm` | 같은 카테고리 최신 3개 |
| — | (데스크톱 사이드 레일) 광고 자리 | 8장 참조 | 본문 오른쪽 바깥 |

- **제거된 것**: 목차 박스, 댓글(Giscus) 영역. h2/h3의 `id` 앵커는 유지(검색엔진의 앵커 링크용).
- AI 방어 숨김 div, 카나리아 문구, JSON-LD(Article + FAQPage)는 v1 그대로.

### 5.3 카테고리 `/category/[이름]/`, 태그 `/tag/[이름]/`

| 요소 | 스타일 | 비고 |
|---|---|---|
| "카테고리" / "태그" | `label`, 초록 | |
| 이름 h1 | `display` | 태그는 `#태그명` |
| "글 N개 · 최신순" | `caption` | |
| 글 목록 | 날짜(`caption`) → 제목(`h3`) → 설명(`body-sm`) | 홈과 같은 형태, 카테고리명 생략 |

- **발행일 내림차순 정렬 필수** (v1의 버그 수정: 정렬 코드 추가).
- 페이지네이션 없음 (글이 많아지면 홈과 같은 방식으로 추가 검토).
- 카테고리 페이지는 헤더 메뉴에서 해당 카테고리가 활성화된다. 태그 페이지는 활성 메뉴 없음.

### 5.4 검색 `/search/`

| 요소 | 스타일 / 동작 |
|---|---|
| 제목 "검색" | `display` |
| 입력창 | 높이 56px(모바일 50px), 돋보기 아이콘, 테두리 1.5px `--ink`, 모서리 10px, 포커스 시 초록 2px 외곽선 |
| 결과 | 제목 링크(`h3`) + 발췌문(`body-sm`, 일치 부분 `--mark` 하이라이트) |
| 결과 없음 | "검색 결과가 없습니다." (`body-sm`) |

- **추가 동작**: 페이지 로드 시 URL의 `?q=` 값이 있으면 입력창에 채우고 바로 검색한다 (헤더 검색에서 넘어오는 경우).
- 그 외 동작(입력 이벤트로 검색, Pagefind 첫 검색 시 로딩, 상위 10개)은 v1 그대로.
- 권장: 첫 로딩 동안 결과 영역에 "검색 중…" 한 줄 표시 (v1은 로딩 표시가 없어 멈춘 것처럼 보임).

### 5.5 소개 `/about/`

1. 제목 "소개" (`display`)
2. 소개 2문단 (`body`)
3. "정보를 확인하는 기준" (`h2`) + 번호 목록 3개 ← 실제 운영 방식과 맞는지 확인 후 확정
   1. 정부·공공기관의 공식 자료를 먼저 확인하고, 글에 출처를 밝힙니다.
   2. 모든 글에 발행일과 마지막 업데이트일을 표시합니다.
   3. 제도가 바뀌거나 오류 제보를 받으면 내용을 고치고 업데이트일을 바꿉니다.
4. 구분선 + "문의: contact@aljjatip.com" (`mailto:` 링크)

- 운영자 소개 섹션은 두지 않는다.

### 5.6 개인정보처리방침 `/privacy/` (신규)

- 제목 + "시행일 [YYYY.MM.DD]" + 본문(글 상세와 같은 본문 스타일: h2 하단 선, 표)
- 섹션: 1 처리하는 개인정보와 목적(표) / 2 보유 기간 / 3 쿠키와 광고 / 4 방문 통계 / 5 제3자 제공 및 처리 위탁 / 6 이용자의 권리 / 7 파기 / 8 개인정보 보호책임자(표) / 9 방침의 변경
- `[ ]` 표시는 운영자가 채울 자리: 시행일, 보유 기간, 분석 도구, 제3자 제공·위탁, 책임자 성명, **책임자 연락처**
- 시안 문구는 초안이다. 게시 전 법률 검토 또는 개인정보보호위원회의 처리방침 작성 지침과 대조할 것.
- 푸터의 "개인정보처리방침" 링크로만 진입. 헤더 메뉴 활성 없음.

### 5.7 404 (신규, `src/pages/404.astro` → `404.html`)

1. "404" (`label`, 초록)
2. "페이지를 찾을 수 없습니다" (`display`)
3. "주소가 바뀌었거나 삭제된 글일 수 있습니다. 아래에서 다시 찾아보세요." (`body`, `--text-2`)
4. 버튼형 링크 2개: "홈으로"(초록 채움) / "검색하기"(테두리) — 높이 48px, 모서리 10px, `strong-sm`

- 카테고리 목록은 두지 않는다 (헤더 메뉴로 충분).

- Cloudflare Pages는 빌드 결과물의 `404.html`을 자동으로 404 응답에 사용한다.

### 5.8 RSS, 시스템 경로

v1 그대로 (`/rss.xml`, 사이트맵, robots.txt, llms.txt, `/pagefind/`). `/privacy/`는 사이트맵에 포함, 404는 제외.

## 6. 이동 흐름

```
헤더(모든 페이지)
  ├─ 로고 ───────────▶ 홈(/)
  ├─ 전체 ───────────▶ 홈(/)
  ├─ 카테고리명 ──────▶ 카테고리(/category/[이름]/)
  └─ 검색 버튼 ───────▶ 검색창 펼침 ──Enter──▶ 검색(/search/?q=…)

홈 ──글 제목──▶ 글 상세
   └─페이지 이동──▶ /2, /3 …

글 상세 ─브레드크럼─▶ 홈 / 카테고리
        ─오류 제보──▶ mailto:support@
        ─태그───────▶ 태그 페이지
        ─이전/다음──▶ 다른 글
        ─관련 글────▶ 다른 글

카테고리 / 태그 / 검색 결과 ──글 제목──▶ 글 상세

푸터(모든 페이지)
  ├─ 소개 ──────────▶ /about/ ──문의──▶ mailto:contact@
  ├─ 개인정보처리방침 ▶ /privacy/
  └─ RSS ───────────▶ /rss.xml

없는 주소 ──▶ 404 ──▶ 홈 / 검색 (+ 헤더 메뉴)
```

## 8. 광고와 공유 이미지

- **AdSense 승인 전에는 광고 영역을 렌더링하지 않는다.** 시안의 점선 박스는 위치 확인용.
- 승인 후 위치:

| 위치 | 크기 | 노출 조건 |
|---|---|---|
| 본문 중간 (인아티클) | 반응형, 높이 약 250px | 데스크톱·모바일 모두 |
| 사이드 레일 | 160×600, 스크롤 따라옴(sticky) | 화면 폭 ≥ 1200px에서만 (본문 오른쪽 바깥, 본문 폭과 겹치지 않음) |

- 각 광고 위에 "광고" 라벨(`label`, `--muted`).
- 300px 폭 레일은 화면 폭 1440px 이상이 필요하다. 레일 폭을 바꾸면 노출 조건도 같이 바꿀 것.
- 넣지 않기로 한 것: 목차 아래·본문 끝 추가 광고, 모바일 하단 고정, 전면(비네트), 자동 광고.

### 8.1 설정 플래그 (권장)

`src/config.ts`에 `ADS_ENABLED`, `ADSENSE_CLIENT`, 슬롯 ID를 두고, 꺼져 있으면 광고 마크업 자체를 출력하지 않는다.

### 8.2 공유 이미지 (OG) 템플릿

- 1200×630, 흰 배경, `--ink` 글자
- 왼쪽 위 로고 이미지(160×67), 오른쪽 위 카테고리 칩(22px, `--table-line` 테두리)
- 가운데 글 제목 64px/700, 최대 2~3줄, 자간 -0.03em
- 아래 왼쪽 `aljjatip.com`, 오른쪽 사이트 설명 (22px, `--muted`)
- 구현: 빌드 시 글마다 생성 (예: `satori` + `@resvg/resvg-js`, 또는 `astro-og-canvas`). 한글 폰트 파일을 빌드에 포함해야 한다.
- `og:image`, `twitter:image`를 글마다 해당 이미지로 지정. 홈·카테고리는 사이트 기본 이미지 1장(`public/social/alzza-og-1200x630.jpg`).

## 9. 접근성 기준

- 터치 영역 최소 44×44 (메뉴, 검색 버튼, 페이지 번호, 푸터 링크)
- 아이콘만 있는 버튼·링크에 `aria-label`
- 장식 SVG는 `aria-hidden="true"`
- 본문 글자 대비 4.5:1 이상 (`--muted` #5b665f는 흰 배경 6.0:1, `--surface` 위 5.6:1 / `--accent` #0b6e4f는 흰 배경 6.25:1)
- `--disabled`는 비활성 표시 전용 (대비 기준 예외)
- 검색 입력창에는 시각적으로 숨긴 `<label>`
