# 정적 블로그 설계서 (인수인계용)

> 이 문서는 AI 코딩 에이전트에게 개발을 지시하기 위한 설계서다.
> 읽는 대상: Claude (개발 담당) / 발주자: DY
> 목표: useful.llily.co.kr 같은 롱테일 질문형 검색 유입 정보 블로그를 내 도메인에 직접 구축

---

## 1. 프로젝트 개요

- **목적**: 일반인이 가끔 검색하는 생활·돈·행정 주제를 정확한 숫자/표/FAQ로 정리한 정보 블로그
- **레퍼런스 구조**: useful.llily.co.kr (도입 요약 → 목차 → 표 중심 섹션 → FAQ → 핵심 요약 → 관련 글)
- **수익 모델**: Google AdSense (글 20~30개 쌓인 뒤 승인 신청)
- **성공 기준**: `npm run build` 한 번으로 전체 사이트가 정적 HTML로 빌드되고, Cloudflare Pages에 배포되면 끝

## 2. 기술 스택 (고정 — 임의 변경 금지)

| 항목 | 선택 |
|---|---|
| 프레임워크 | Astro 4.x (SSG, `output: 'static'`) |
| 스타일 | Tailwind CSS |
| 호스팅 | Cloudflare Pages (GitHub 연동 자동 배포) |
| 댓글 | Giscus (GitHub Discussions 기반) |
| 사이트 내 검색 | Pagefind (빌드 시 정적 인덱스) |
| 분석 | Cloudflare Web Analytics |
| 패키지 | `@astrojs/sitemap`, `@astrojs/rss` |
| Node | 20+ |

**금지**: SSR, DB, 인증, 관리자 화면, 워드프레스식 플러그인 구조. 전부 제외.

## 3. 정보 아키텍처 (라우트)

| 경로 | 내용 |
|---|---|
| `/` | 홈 — 최신 글 목록 (10개씩 페이지네이션), 카테고리 네비 |

## 4. 콘텐츠 모델 (frontmatter 스키마)

`src/content/posts/*.md` — 파일명이 slug가 된다.

```yaml
---
title: "쿠팡 알바 시급 얼마? 2026년 야간·주말 수당까지 계산법 총정리"  # 필수
description: "2026년 기준 쿠팡 알바 시급 10,320원. 야간·주말·공휴일 수당 계산법과 실수령 예시"  # 필수 (120~160자)
date: 2026-10-30        # 필수, 발행일
updated: 2026-11-02     # 선택, 갱신일 (있으면 페이지에 "업데이트됨" 표시)
category: "세금"    # 필수
tags: ["쿠팡", "알바", "시급"]  # 선택
draft: false             # 선택, true면 빌드에서 제외
---
```

- 필수값 누락 시 빌드 에러를 내도록 Content Collections 스키마(zod)로 검증할 것
- 본문은 마크다운/MDX, 표·인용·콜아웃 지원

## 5. 페이지별 명세

### 5.1 글 상세 (`/posts/[...slug]/`) — 가장 중요

위에서 아래 순서대로 렌더링:

1. 브레드크럼 (홈 > 카테고리 > 글제목)
2. `h1` 글 제목 (페이지당 h1은 하나만)
3. 메타 정보: 발행일, 갱신일(있을 때), 카테고리, 읽기 시간
4. **도입 요약 박스**: 3줄 핵심 요약 (검색 스니펫에 걸리는 부분)
5. **목차 (TOC)**: h2/h3 기반 자동 생성, 스크롤 스파이
6. 본문
7. **FAQ 섹션**: frontmatter나 본문 하단에 Q/A 목록 → FAQPage JSON-LD와 1:1 매칭
8. **핵심 요약 박스**: 3~5줄
9. 태그 목록
10. 이전 글 / 다음 글
11. 관련 글 3개 (같은 카테고리 우선, 없으면 최신 글)
12. 댓글 (Giscus)

SEO 헤드:
- `<title>{글제목} | {사이트명}</title>`
- meta description = frontmatter description
- canonical = 절대 URL
- OG / Twitter 카드 (og:image는 기본 이미지 1장으로 통일해도 됨)
- Article JSON-LD + FAQPage JSON-LD

### 5.2 홈 / 목록 페이지

- 최신 글 카드 목록: 제목, 2줄 요약, 날짜, 카테고리 뱃지
- 페이지네이션 (10개 단위)
- 카테고리 네비게이션

### 5.3 전역 설정 파일

`src/config.ts` 하나에 전부 모을 것. 하드코딩 금지.

```ts
export const SITE = {
  name: "알짜",
  url: "https://aljjatip.com",  // 마지막 슬래시 없음
  description: "생활·돈·행정 — 알아두면 쓸모있는 정보",
  author: "DY",
};
export const GISCUS = { repo: "...", repoId: "...", category: "...", categoryId: "..." };
// Giscus 값은 발주자가 GitHub에서 발급받아 입력
```

## 6. SEO 스펙

- 시맨틱 HTML (`article`, `nav`, `main`, `time` 등)
- 모든 이미지 `alt` 필수, `loading="lazy"`
- `sitemap-index.xml`에 전 페이지 포함, `robots.txt`에서 sitemap 경로 명시
- RSS에 전체 본문 포함 (피드 리더 대응)

## 7. GEO/AEO 스펙 (AI 검색 인용 대비)

### llms.txt (`public/llms.txt`)

```
# 알짜
> 생활·돈·행정 — 알아두면 쓸모있는 정보

## 카테고리명
- [글 제목](https://aljjatip.com/posts/slug/): 한 줄 요약
```

- 빌드 시 전체 글 목록에서 **자동 생성**할 것 (수동 관리 금지)

### JSON-LD

- 글 상세: `Article` (headline, description, datePublished, dateModified, author) + `FAQPage` (FAQ 섹션과 동일 내용)
- 홈: `WebSite` (+ `SearchAction`은 사이트 내 검색이 Pagefind 기반이므로 생략 가능)

### 글 구조 가이드 (에디터용이 아니라 템플릿/문서로 포함)

- 결론 먼저 → 근거 표 → FAQ 순서 권장
- 숫자는 반올림하지 말고 정확히, 출처(법령·고시 등) 명시 권장

## 8. AI 카피 방어 스펙

### robots.txt (`public/robots.txt`) — 그대로 사용할 것

```
# 학습용 크롤러 차단. PerplexityBot은 검색 크롤러(Perplexity 공식: 파운데이션 모델 학습에 미사용)라 허용 목록에 둠
User-agent: GPTBot
User-agent: CCBot
User-agent: ClaudeBot
User-agent: Google-Extended
User-agent: Bytespider
User-agent: meta-externalagent
User-agent: Applebot-Extended
Disallow: /

# 검색·온디맨드 봇 허용 (AI 답변 인용·노출용)
User-agent: ChatGPT-User
User-agent: OAI-SearchBot
User-agent: Claude-User
User-agent: Claude-SearchBot
User-agent: PerplexityBot
User-agent: Perplexity-User
Allow: /

User-agent: *
Allow: /

Sitemap: https://aljjatip.com/sitemap-index.xml
```

- 도메인은 aljjatip.com로 확정됨
- 주의: Google-Extended 차단은 Googlebot 검색 인덱싱과 무관함. 절대 Googlebot을 Disallow하지 말 것

### 숨김 방어 프롬프트

- 글 상세 레이아웃의 본문 시작 직후에 삽입 (독자에게 보이지 않음)
- 형태: HTML 주석 + 1px div (구체 문구는 발주자가 별도 제공)
- 삽입 위치를 `src/layouts/Post.astro`에 상수로 분리해 둘 것

### 카나리아 문자열

- 글 본문 하단에 눈에 띄지 않는 고유 문자열 삽입 (무단 복제 탐지용)
- 형식은 발주자가 별도 제공

## 9. 디자인 가이드

- 톤: **깔끔, 여백 충분, 낮은 AI슬롭**. 과한 애니메이션·그라디언트 남발·이모지 남발 금지
- 본문 타이포: 17~18px, 행간 1.7~1.8, 본문 최대 너비 720px
- 색상: 중립 그레이 + 포인트 컬러 1개. CSS 변수로 정의
- 표 스타일: 헤더 행 구분 명확, 모바일에서 가로 스크롤
- 콜아웃 박스 3종: 정보(파랑), 주의(노랑), 요약(회색) — 남발 금지
- 다크모드: Phase 1에서 제외, Phase 2에서 검토
- 반응형 필수 (모바일 우선)

## 10. 빌드 / 배포

- `npm run build` → `dist/` 정적 출력, 에러 0개
- GitHub main 브랜치 푸시 → Cloudflare Pages 자동 배포
- 빌드 후 Pagefind 인덱싱이 자동 실행되도록 빌드 스크립트에 포함 (`postbuild` 등)
- 환경변수 없음 (Giscus 설정값은 `src/config.ts`에)

## 11. 작업 단계

- **Phase 1**: 스캐폴딩 + 전역 설정 + 홈/글 상세 레이아웃 + SEO 기본기 → 배포 후 URL 공유
- **Phase 2**: 카테고리/태그/소개 페이지 + sitemap/RSS + Pagefind + Giscus
- **Phase 3**: llms.txt 자동 생성 + JSON-LD + AI 카피 방어 3종 + 검색엔진 등록 가이드 문서
- 각 Phase 완료 후 발주자 확인 → 다음 Phase 진행

## 12. 인수 기준 (Acceptance Criteria)

- [ ] `npm run build` 성공, `dist/`에 전 페이지 정적 HTML 출력
- [ ] Lighthouse: SEO 100, Performance 95+ (모바일 기준)
- [ ]  `/sitemap-index.xml`, `/robots.txt`, `/llms.txt`, `/rss.xml` 직접 접근 가능
- [ ] 샘플 글 3개로 홈→글→관련 글→댓글 전체 플로우 동작 확인
- [ ] robots.txt에 8장의 크롤러 규칙이 그대로 반영됨
- [ ] `src/config.ts`의 값만 바꾸면 사이트명·도메인·Giscus가 전부 바뀌는 구조
